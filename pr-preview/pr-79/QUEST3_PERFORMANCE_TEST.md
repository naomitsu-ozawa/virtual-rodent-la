# Quest 3の描画性能テスト

対象はCodexの専用ブランチ `codex/quest3-render-perf-20260930`、build 369。2026年10月1日の実機確認用。main build 360から分岐し、別AIのPR 78には変更を加えていない。

この版は空領域判定をRG32FのCT範囲比較からR8UIの存在ビットへ置き換える。加工で完全に消えたブロックではCT・マスクの参照も省く。データ解像度、探索刻み、6回の境界補正、陰影は維持する。同じブロックの判定再利用と高速な表面補正は別AIの作業と重なるため、この版には入れていない。

## 開き方

このPRのGitHub PagesプレビューURLに `?vrperf=1` を付け、Quest Browserで開く。PR番号と公開URLはPRの説明・プレビューのコメントを参照する。

性能比較用URLでは、512³データ・標準の探索刻みを固定し、画面倍率の自動低下を無効にする。初回の画面倍率は100％。設定は性能比較用の別キーに保存し、通常版のVR設定を上書きしない。次回も画面倍率は保存した固定値になる。リフレッシュレートは対応する72Hz以上の最小値で開始する。

「練習データ（512³）」または普段のDICOMを開き、複数セグメントと加工を設定してから「VRで見る」または「ARで見る」で準備・開始する。大きなテクスチャ転送とシェーダーのコンパイル完了を、VR開始前のページで待つ。VRに入った直後は3D停止中で、メニューだけを描く。「表示」の「3Dを開始／再開」で開始する。準備の「空領域の事前判定」は初回だけで、同じデータと加工では再利用される。

## 遅延時の停止

`?vrperf=1` ではフレーム間隔が予算の1.4倍を3回連続で超えた場合、または1回100ms以上になった場合、次のボリューム描画を停止する。GPUタイマーが使える場合はボリューム描画を含むパスが予算の1.15倍を3回連続、または1回50ms以上でも停止する。メニューを開き、3Dは自動で再開しない。データ解像度・探索刻み・画面倍率を自動で下げない。

停止したら、モデルを小さくしてから「3Dを開始／再開」を押す。停止条件でもメニュー、コントローラー、終了操作を処理する。追加描画と同期読み戻しを伴うVR内スクリーンショットはこのURLでは無効にする。

この保護は遅延の観測後に働く。すでにGPUに送った処理をキャンセルできず、最初の遅いフレーム、GPUドライバーの停止、タイマーが返るまでの遅延を完全に防ぐ保証はない。実機でメニュー復帰と終了操作も必ず確認する。保護による停止は70fps達成に数えず、性能不足として記録する。

## 同じ解像度で比較する

1. 「画質」でデータ512³・描画の細かさ「標準」を確認する。画面倍率は100％で比較する。普段の固定倍率を比較する場合も、従来と高速で同じ値を使う。
2. 「表示」で、比較するセグメントをすべて「通常」にする。透明度も比較中は変えない。
3. 形状を普段重くなる大きさまで拡大し、位置・向きを決める。
4. 「詳細」の「高速探索」で「従来」を選び、数秒待ってからfps、ボリュームms、本描画ms、表示されているデータ寸法と画面倍率を記録する。
5. 位置や画質を変えずに「高速」を選び、同じ項目を記録する。
6. 従来→高速→従来の順に複数回比較する。温度や偶然の負荷の差を減らすため、最後に数分間使った状態でも比較する。

詳細の末尾のRG32Fは従来、R8は高速の印。GPUタイマーが使えない場合、ms欄は「–」になる。その場合もfpsと描画条件を記録する。

100％で遅い場合、倍率を下げた結果を「解像度を維持して70fpsを達成した」とは扱わない。比較前後の倍率が同じでも、100％と異なる倍率の結果は分けて記録する。

## 確認する場面

- 3D停止中にメニュー操作・終了ができること。負荷保護による停止後、勝手に再開しないこと。
- 2セグメントと4セグメント。加工で空領域が増える条件と、加工なしの条件。
- 細い骨、複雑形状、拡大表示。従来と高速で欠落、段差、色、輪郭が変わらないか。

## ローカルで確認できたこと

実物のGLSLをWebGL2で実行し、main build 360の保存したシェーダー、今回の従来モード、高速モードの画像を比較した。加工マスク、4セグメント、分類データ、4枚の断面、内部視点、異なるグリッド寸法を含む12条件でRGBAが完全一致した。

外から見るHU描画の加工あり合成データ条件ではCT参照が約7〜23％減り、空領域判定の参照はRG32FからR8UIへ置き換わった。512³のブロック情報は1方式あたり2MiBから256KiBになる。比較用に従来の情報も保持するので、このテスト版でGPUメモリの総使用量が減ったという意味ではない。

内部視点の条件ではCT参照の減少は約5％。分類データを使う条件ではCT参照は変わらず、分類テクスチャの参照が約11％減った。

これらは画像の回帰確認と処理回数の計測であり、Quest 3のfps計測ではない。実機でGPU時間が短くなるか、70fpsを超えて安定するかはこのテストで判断する。高速モードが遅い場合は従来モードへ戻し、その結果も記録する。

開発用の再現コマンドは `PW_CHROMIUM=/usr/bin/chromium node tools/vr-brick-check.mjs`。通常のPlaywrightブラウザがインストール済みなら `PW_CHROMIUM` は省略できる。
